## 4. 必须修复的缺陷（P0）

### 4.1 发送请求报 `unsupported protocol scheme ""`（用户主诉）

**复现**：URL 输入 `www.baidu.com`（无 `http://`）→ 发送 → `services/http_service.go:61` 把裸串交给 `http.NewRequest` → Go 报错。

**修复**：
1. **后端兜底** —— `SendRequest` 入口加 `normalizeURL(raw string) (string, kind string)`：
   - 已含 `://` → 原样返回。
   - 形如 `localhost` / `127.0.0.1` / `[::1]` / `*.local` / 带端口 `:3000` → 补 `http://`。
   - 其他无 scheme → 补 `https://`。
   - 补全后仍无法 `url.Parse` 或 host 为空 → 返回 `kind = "bad_url"`，不发请求。
2. **前端预览** —— URL 输入框内实时灰显补全结果（如输入 `www.baidu.com` 时尾部/前缀提示 `https://`）。是否自动补全受 `settings.autoCompleteScheme`（默认 true）控制（SET-4）。
3. **错误友好化** —— `HTTPResponse` 新增 `errorKind` 字段，取值 `bad_url | dns | timeout | tls | refused | canceled | other`；前端响应区错误卡片按 kind 显示中文标题 + 可能原因 + 操作按钮（`补全并重试` / `编辑 URL` / `重试`）。Go 侧分类逻辑：`errors.Is(err, context.DeadlineExceeded)`→timeout；`*net.DNSError`→dns；`x509.*` / `tls.*`→tls；`syscall.ECONNREFUSED`→refused；`context.Canceled`→canceled。

### 4.2 Query 拼接未做 URL 编码

`buildURLWithQuery`（`http_service.go:132`）直接字符串拼 `key=value`，含空格/中文/`&` 会拼坏。**改用 `net/url`**：`u.Query()` 逐个 `q.Add(k, v)` 后 `u.RawQuery = q.Encode()`。

### 4.3 `api/backend.ts` 过时注释

删除文件里"首次运行前 IDE 会报找不到模块，属于正常现象"等注释；`frontend/bindings/voltra/services` 已存在。

## 5. 后端接口契约（Go services ↔ 前端）

前端统一经 `src/api/backend.ts` 再导出，不要在业务组件里直接 import `bindings/`。

### 5.1 HTTPService

**现状**：`SendRequest(req: HTTPRequest): CancellablePromise<HTTPResponse>`（Call ID 自动）。

**改造后 `HTTPRequest`（Go struct + json tag）**——在现有字段基础上增加：

| 字段 | 类型 | 说明 |
|------|------|------|
| `method` `url` `headers` `query` `body` | 同现状 | `headers`/`query` 为 `[]KVPair` |
| `bodyType` | string | `none\|form-data\|urlencoded\|raw\|binary\|graphql`（注意：**改掉**现状里的 `json`，JSON 属于 `raw` + `rawLang`） |
| `rawLang` | string | `json\|xml\|text\|html`，仅 `bodyType=raw` |
| `formData` | `[]FormField` | `type: text\|file`，file 用 `filePath` |
| `binaryPath` | string | |
| `timeoutMs` | int | 取代 `timeoutSeconds` |
| `followRedirects` | bool | |
| `maxRedirects` | int | |
| `insecureSkipTlsVerify` | bool | 同现状 |
| `sendCookies` | bool | |
| `requestId` | string | 前端生成，用于取消与计时关联 |

**改造后 `HTTPResponse`** 增加：`errorKind string`（见 §4.1）；`timings`（P1，`{dnsMs,tcpMs,tlsMs,ttfbMs,downloadMs}`，用 `net/http/httptrace`）。

**取消**：优先利用 Wails 生成的 `CancellablePromise`——前端 `const p = HTTPService.SendRequest(req); p.cancel()`。Go 侧 `SendRequest` 需接收 Wails 注入的 `context.Context`（v3 支持），并透传给 `http.NewRequestWithContext`。若该注入在当前 beta 不可用，则退化为显式 `Cancel(requestId string)` 方法 + Go 侧维护 `map[requestId]context.CancelFunc`。**实施时先验证哪种可用，并在 §9 回填结论。**

**变量替换发生在前端**：前端发起前对 `url/query/headers/body/auth` 做 `{{var}}` 替换，Go 收到的是已替换的最终值。Go 不感知变量。

### 5.2 StorageService

**现状方法**：`GetDataDir()`、`LoadCollections()/SaveCollections(data)`、`LoadEnvironments()/SaveEnvironments(data)`、`LoadHistory()/SaveHistory(data)`。全部是 `string` JSON 文本进出，空文件返回 `"[]"`。

**新增方法**（签名与现有一致，纯 JSON 文本存取）：

```go
LoadProjects() (string, error)          // 读 projects.json，缺省 "[]"
SaveProjects(data string) error
LoadSettings() (string, error)          // 读 settings.json，缺省 "{}"
SaveSettings(data string) error
LoadUIState() (string, error)           // 读 ui-state.json，缺省 "{}"
SaveUIState(data string) error
OpenDataDirInFileManager() error        // SET-2：调用系统文件管理器打开 baseDir
ExportAllData() (string, error)         // SET-2：返回一个打包好的 JSON（或写 zip 到用户选择路径）
```

- `LoadCollections/SaveCollections` **保留**，仅用于旧数据迁移读取（见 §7 迁移）。
- 保持"写临时文件 + 原子 rename"策略（已实现）。
- **启动健壮性**：`load` 时若 JSON 解析失败（新增：Go 侧不解析，改由前端解析失败时处理），前端捕获后把坏文件另存 `*.corrupt.<时间戳>`（需要 Go 提供 `BackupCorruptFile(filename string)` 或前端读到内容自行判断——**二选一，实施时定，记 §9**），并以空数据继续。

### 5.3 WSService（基本不改）

方法：`Connect(url: string, headers: KVPair[]) : Promise<connId: string>`、`Send(connId, message)`、`Close(connId)`、`ListConnections(): string[]`。

事件（`@wailsio/runtime` 的 `Events.On`）：
- `ws:message` → `{ connId, message, isBinary, timestamp }`
- `ws:status` → `{ connId, status: 'connected'|'closed'|'error', detail? }`

**v0.2 需补**：`Send` 增加二进制帧支持（新增 `SendBinary(connId, base64)` 或给 `Send` 加 `isBinary` 参数）；握手 headers 前端已能传，接好 UI 即可。

## 7. 数据：模型、落盘、迁移

### 7.1 模型
以 `需求文档.md §7` 的 TypeScript 定义为准。补充说明：

- `需求文档.md §7` 里 `Request.examples?: Example[]` 引用的 `Example` 类型定义如下（v0.2 只存不展示，属 REQ-13/P2，但类型先占位）：
  ```ts
  interface Example {
    id: ID
    name: string
    request: Request          // 请求快照
    response?: {              // 可选：保存的响应快照
      statusCode: number
      headers: KVPair[]
      body: string
    }
  }
  ```
- **环境的存储**：`Environment` 内嵌在 `Project.environments` 里（每个项目自己的 dev/test/prod）。`environments.json` 这个**独立文件仅存"全局变量"**（跨项目、最低优先级的一组 `Variable[]`）。项目级变量是 `Project.variables`。四层优先级：`请求级 > 环境级(当前项目当前环境) > 项目级(Project.variables) > 全局(environments.json)`。
- `{{var}}` 语法：`{{` + 变量名（`[A-Za-z0-9_.$-]+`）+ `}}`。`{{$xxx}}` 保留给动态内置变量（ENV-7/P2）。未匹配到定义的变量：不替换、原样保留，并在 UI 标红告警（ENV-4）。

### 7.2 落盘文件（在 §11 数据目录下）

| 文件 | 内容 | 触发写入 |
|------|------|---------|
| `projects.json` | `Project[]` | 树/接口任何结构或内容变更，debounce 500ms |
| `environments.json` | `Variable[]`（全局变量） | 全局变量编辑 |
| `history.json` | `HistoryEntry[]`，按 `sentAt` 倒序，超 `settings.historyLimit`(默认 500) 裁剪 | 每次发送后 |
| `settings.json` | 应用设置对象 | 设置变更即时 |
| `ui-state.json` | `{ openTabs, activeTabId, sidebarWidth, splitRatio, splitDir, expandedNodeIds, lastProjectId, lastEnvId }` | 变更 debounce 1s；可容忍丢失 |

### 7.3 旧数据迁移（启动时一次）

1. 若 `projects.json` 不存在但 `collections.json` 存在且非 `"[]"`：把它解析为 `Collection[]`，包一层默认 `Project`（name `默认项目`，新 uuid，`environments: []`，`variables: []`），写入 `projects.json`；把 `collections.json` 重命名为 `collections.json.migrated-<时间戳>`。
2. 若都不存在：`projects.json` 写 `[]`，前端进入**空状态引导**（TREE-7）。
3. 迁移任何异常都不得让应用崩溃——失败则记录日志、以空数据启动。
