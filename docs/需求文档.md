## 1. 背景与问题

Voltra 定位为"轻量级跨平台 API 接口调试工具"，目标对标 Postman / Apifox 的核心调试体验，但更轻、启动更快、纯本地、开源。

当前 MVP 骨架存在三个致命问题（来自使用反馈）：

| # | 问题 | 现状 | 影响 |
|---|------|------|------|
| 1 | 界面简陋，与 Postman/Apifox 差距过大 | 单页面、无侧边栏、无主题、无标签页 | 第一印象差，不像成熟工具 |
| 2 | 无法以"项目"形式管理接口 | `StorageService` 有存储能力但前端完全没接入；没有集合/分组/树 | 只能发一次性请求，无法沉淀，作为开源项目没有使用价值 |
| 3 | 发请求直接报错 | 输入 `www.baidu.com` → `unsupported protocol scheme ""` | 基本功能不可用 |

### 3 号问题根因分析

`services/http_service.go:61` 直接把用户输入的 URL 交给 `http.NewRequest`。当用户输入 `www.baidu.com`（无 `scheme`）时，Go 标准库报 `unsupported protocol scheme ""`。

**修复策略**（本次重构一并处理）：
- 前端 URL 规范化：输入无 `://` 前缀时自动补 `https://`，输入框内实时灰显提示补全后的完整 URL。
- 后端兜底：`SendRequest` 内对 `req.URL` 做 `normalizeURL()`，无 scheme 时补 `https://`，`localhost`/`127.0.0.1`/`:端口` 场景补 `http://`。
- 错误信息友好化：把 Go 原始 error 翻译成"URL 缺少 http:// 或 https:// 前缀""域名无法解析""连接超时"等中文可读提示。

## 2. 目标与非目标

### 2.1 本次重构目标（v0.2）

1. **重做整体信息架构与视觉**：活动栏 + 侧边栏 + 多标签页工作区 + 请求/响应分栏，明暗主题，达到"看起来像专业工具"的水准。
2. **落地项目化接口管理**：工作空间 → 项目 → 集合 → 文件夹 → 接口 的树形组织，可增删改、拖拽排序、重命名、复制。
3. **打通持久化**：树、环境、历史全部通过 `StorageService` 落盘并在启动时恢复。
4. **修复并加固请求发送链路**：URL 规范化、错误友好化、超时/重定向/TLS 可配置。
5. **环境与变量**：环境下拉切换 + `{{变量}}` 替换，覆盖 URL / Query / Header / Body。
6. **导入导出**：至少支持 Postman Collection v2.1、cURL 文本，和 Voltra 自有 JSON 格式。
7. **生成代码**：把当前请求一键转成 cURL / Python / JavaScript / Java / PHP / Go 等主流语言的客户端代码（见 §5.3.1）。

### 2.2 非目标（明确不做 / 后续版本）

- 团队协作 / 云同步 / 账号体系（保持纯本地、开源）。
- Mock Server、自动化测试编排、CI 集成（排期 v0.4+）。
- 完整 OpenAPI 3 双向同步（v0.3 先做只读导入）。
- gRPC / GraphQL 专用面板（v0.4+，当前 GraphQL 可用 raw body 凑合）。
- 性能压测 / 定时任务。

## 4. 信息架构

```
Workspace（工作空间，本地默认 1 个，可建多个）
└── Project（项目）
    ├── Collection（集合）
    │   ├── Folder（文件夹，可嵌套）
    │   │   └── Request（接口：HTTP / WebSocket）
    │   └── Request
    ├── Environments（环境：Global / dev / test / prod ...）
    └── Variables（项目级变量）

History（请求历史，按时间倒序，跨项目）
```

- 侧边栏活动栏（Activity Bar）标签：**集合**、**环境**、**历史**、**运行器（占位，v0.4）**、**设置**。
- 一个接口（Request）是可持久化的完整请求定义，双击在新标签页打开。

#### 5.3.1 生成代码（Code Snippet）

**入口**：URL 栏右侧 `</>` 图标；接口树右键菜单"复制为代码"；命令面板。

**行为**：打开右侧抽屉/弹窗，左侧选「语言 + 客户端库」，右侧实时生成代码，顶部 `复制` / `在编辑器打开`。可切换"使用变量原样 `{{token}}`"或"用当前环境 dev 的真实值替换"。表单/二进制 body、Auth、启用的 Header/Query 均如实反映。

**支持矩阵**（P1 = 首批；P2 = 后续按需补齐）：

| 语言 | 客户端 | 优先级 |
|------|--------|--------|
| Shell | cURL | **P1** |
| Shell | HTTPie、wget | P1 |
| Python | requests | **P1** |
| Python | http.client（标准库） | P1 |
| JavaScript | fetch | **P1** |
| JavaScript | Axios、XMLHttpRequest、jQuery.ajax | P1 |
| Node.js | 原生 http/https、node-fetch、Axios | P1 |
| Java | OkHttp | **P1** |
| Java | java.net.http（JDK 11+）、Unirest、HttpURLConnection | P1 |
| PHP | cURL（ext-curl） | **P1** |
| PHP | Guzzle、HTTP_Request2 | P1 |
| Go | net/http | **P1** |
| C# | HttpClient、RestSharp | P1 |
| Ruby | net/http | P1 |
| Swift | URLSession | P1 |
| Kotlin | OkHttp | P1 |
| Rust | reqwest | P2 |

| R / Clojure / Elixir / Perl | 各自主流库 | P2 |

**实现方案**：前端集成 HTTP Snippet 生成库（`httpsnippet` 系，Postman/Insomnia 同源方案，纯前端、离线、体积可控），把 Voltra 的 `Request` 模型先转为 HAR request 结构再交给该库；不在 Go 侧实现。自定义模板（P2）允许用户增删语言片段。

**验收**：cURL / Python requests / JavaScript fetch / Java OkHttp / PHP cURL / Go net/http 六项生成的代码可直接复制运行且与 Voltra 实际发出的请求等价（method、URL、query、header、body、auth 一致）。

## 7. 数据模型（TypeScript，前端维护，落盘为 JSON）

```ts
type ID = string // uuid

interface Project {
  id: ID
  name: string
  collections: Collection[]
  environments: Environment[]
  variables: Variable[]          // 项目级变量
  createdAt: number
  updatedAt: number
}

interface Collection {
  id: ID
  name: string
  description?: string
  auth?: AuthConfig              // 子节点默认继承
  headers?: KVPair[]             // 公共 header
  items: TreeNode[]
}

type TreeNode = Folder | Request

interface Folder {
  kind: 'folder'
  id: ID
  name: string
  auth?: AuthConfig
  headers?: KVPair[]
  items: TreeNode[]
}

interface Request {
  kind: 'request'
  id: ID
  name: string
  protocol: 'http' | 'ws'
  method: string                // http 用；ws 忽略
  url: string
  params: KVPair[]              // query
  headers: KVPair[]
  body: RequestBody
  auth: AuthConfig
  settings: RequestSettings
  preRequestScript?: string
  testScript?: string
  examples?: Example[]
  updatedAt: number
}

interface RequestBody {
  type: 'none' | 'form-data' | 'urlencoded' | 'raw' | 'binary' | 'graphql'
  raw?: string
  rawLang?: 'json' | 'xml' | 'text' | 'html'
  formData?: FormField[]
  urlencoded?: KVPair[]
  binaryPath?: string
  graphql?: { query: string; variables: string }
}

interface RequestSettings {
  timeoutMs: number
  followRedirects: boolean
  maxRedirects: number
  insecureSkipTlsVerify: boolean
  sendCookies: boolean
}

interface AuthConfig {
  type: 'none' | 'inherit' | 'bearer' | 'basic' | 'apikey'
  bearer?: { token: string }
  basic?: { username: string; password: string }
  apikey?: { key: string; value: string; in: 'header' | 'query' }
}

interface Environment {
  id: ID
  name: string
  variables: Variable[]
}

interface Variable {
  key: string
  initialValue: string
  currentValue: string
  enabled: boolean
  secret?: boolean
}

interface KVPair { key: string; value: string; enabled: boolean; description?: string }
interface FormField extends KVPair { type: 'text' | 'file'; filePath?: string }

interface Example {                // REQ-13 / P2；v0.2 只定义类型不做 UI
  id: ID
  name: string
  request: Request                 // 请求快照
  response?: { statusCode: number; headers: KVPair[]; body: string }
}

interface HistoryEntry {
  id: ID
  requestSnapshot: Request       // 完整快照，便于还原
  responseSummary: { statusCode: number; durationMs: number; sizeBytes: number }
  sentAt: number
}
```

**变量语法**：`{{` + 名称（`[A-Za-z0-9_.$-]+`）+ `}}`。`{{$name}}` 保留给动态内置变量（ENV-7 / P2）。作用域优先级：**请求级 > 环境级（当前项目 + 当前环境）> 项目级（`Project.variables`）> 全局（`environments.json`）**。未匹配到定义的 `{{x}}`：不替换、原样保留，UI 标红告警（ENV-4）。替换在**前端发送前**完成，Go 侧收到的是最终值。

落盘文件（沿用现有 `StorageService`，目录见 §11）：
- `projects.json` —— `Project[]`（原 `collections.json` 升级；迁移时自动包裹为一个默认 Project）
- `environments.json` —— 兼容保留，实际环境已内嵌 Project；此文件存"全局变量"
- `history.json` —— `HistoryEntry[]`
- `settings.json` —— 应用设置（新增）
- `ui-state.json` —— 打开的标签、侧边栏宽度、分栏比例、展开的树节点（新增，可选）

### Go 侧新增绑定方法（`StorageService`）

### Go 侧 `HTTPService` 改造

- `SendRequest`：入口加 `normalizeURL`；错误分类为 `errKind`（`bad_url` / `dns` / `timeout` / `tls` / `refused` / `other`），返回结构新增 `errorKind` 字段。
- 新增 `SendRequestStream`（P1）：大响应体分块通过事件推送；或先用同步 + 大小上限。
- 新增 `Cancel(requestId string)`：配合前端"取消"按钮，用 `context.WithCancel`。
- 请求前把 `RequestSettings` 落到 `http.Client`（超时、重定向策略、TLS）。
- 计时拆解（P1）：用 `httptrace` 采集 DNS/连接/TLS/TTFB。

## 8. 关键交互流程

### 8.1 首次启动
无项目 → 主区空状态卡片：`新建项目` / `导入 Postman 集合` / `从 cURL 创建`。选任一后进入正常界面。

### 8.2 新建并保存一个接口
右键集合 → 新建请求 → 新标签页打开（标题"未命名请求"，带未保存圆点）→ 填 method/url/body → `Cmd+S` → 若已有归属直接存，否则弹"保存到"对话框选集合/文件夹并命名 → 圆点消失，树中出现节点。

### 8.3 发送请求
点发送 → 变量替换（`{{}}`）→ URL 规范化 → 调 `HTTPService.SendRequest` → 按钮变"取消" → 响应回填 + 写历史。失败 → 响应区错误态 + 原因 + 重试。

### 8.4 切换环境
顶部下拉选 `dev` → 所有标签页的变量预览、发送时替换均使用 dev 值；不改动接口定义本身。

### 8.5 导入 Postman
设置/树顶部"导入" → 选 `.json` → 解析 v2.1 → 预览将创建的集合/文件夹/接口数量 → 确认 → 生成到当前项目。

## 10. 验收标准（v0.2）

1. 输入 `www.baidu.com` 点发送能正常拿到响应（自动补 `https://`）；断网时显示中文错误 + 重试按钮。
2. 能新建项目 → 集合 → 文件夹 → 接口，重启应用后树、标签、主题、侧栏宽度均恢复。
3. 至少同时打开 5 个接口标签页互不串数据，未保存有圆点提示。
4. 定义环境 `dev` 含 `{{baseUrl}}`，接口 URL 写 `{{baseUrl}}/users` 能正确请求。
5. 导入一个真实 Postman v2.1 集合，接口数量、层级、method、URL、body 一致。
6. 明暗主题切换全界面无残留浅色/深色块。
7. 1000 接口的树搜索输入即时过滤无明显卡顿。
8. 视觉走查：与 Apifox/Postman 并排，布局密度、控件、配色达到"同类专业工具"观感（评审主观通过）。

## 12. 风险

| 风险 | 应对 |
|------|------|
| Wails v3 仍是 beta.3，事件/绑定 API 可能变动 | 绑定层封装在 `api/backend.ts` 单点适配；关注官方 issue |
| 前端自研代码编辑器（高亮/折叠）工作量大 | 引入 CodeMirror 6（体积可控），不自研 |
| Postman schema 边角 case 多 | v0.2 只承诺常见字段，解析失败项跳过并给出报告 |
| 大响应体渲染卡顿 | 超过 1MB 默认折叠 + 仅 Raw；Pretty 需手动触发 |
| 现有用户 `collections.json` 数据迁移 | 启动检测旧文件，自动包一层默认 Project 写入 `projects.json`，保留旧文件备份 |
